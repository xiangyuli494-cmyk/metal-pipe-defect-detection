## 三、发现并修复的缺陷（共 7 个，均为真实功能缺陷）

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | **模型从不加载**：`predict_from_path` 失败时路由仍返回 `200 + 0 缺陷`，页面显示"检测完成，未发现缺陷" | 核心检测功能形同虚设 | `main.py` 增加 `@app.on_event("startup")` 自动加载 `models_weights/best.pt`；推理失败改为抛 503 而非伪装成功 |
| 2 | **bcrypt 5.0 与 passlib 1.7.4 不兼容**，`hash()` 全部抛 `password cannot be longer than 72 bytes` | 创建用户 / 重置密码 / 修改密码全部 400 失败 | 新增 `backend/services/password_util.py`（原生 bcrypt），替换 `database_service.py` 中 5 处调用；保留 MD5 旧密码兼容并自动升级 |
| 3 | `create_batch_detection` 缺 `conn.commit()` | 批次数据未落库 → 详情 404、进度为空 | 补 `conn.commit()` |
| 4 | `get_batch_detections` SQL 引用不存在的列 `bd.user_id` | 异常被 `except` 吞掉返回 `[]` → 批量详情永远 404 | 改为 `LEFT JOIN users u ON u.username = bd.username` |
| 5 | `get_detection_record` 的 `finally:` 里写了 `return None` | **覆盖 try 中的正常返回，所有记录详情 404** | 删除 `finally` 中的 `return`，仅保留 `conn.close()`；全后端 AST 扫描确认无残留 |
| 6 | 批量接口 `batch_id: int`，但批次号是 UUID 字符串 | 详情 / 进度接口 422 | 改为 `str`，新增 `_match_batch_id()` 同时兼容 `id` 与 `batch_id` |
| 7 | 前端 `useCameraDetection.ts` 中 `stopDetection` 在 `startDetection` 之后声明（TDZ）；`CameraDetectionPage.tsx` 多一个 `)}` | 摄像头页面一打开就白屏崩溃 | 调整声明顺序；删除多余 `)}` |

### 顺带修正的安全与健壮性问题

- 新增 `except HTTPException: raise`，避免自定义 4xx 被通用 `except Exception` 吞成 500（约 50 处）
- 批量接口的操作员身份改为取自 JWT（`current_user`），不再信任请求体中的 `user_id`
- `model_service.predict_from_path` 用 `time.perf_counter()` 真实统计推理耗时（此前恒为 0/缺失）
- 补齐 28 个路由的 `Depends(get_current_user)` 鉴权；修复 `/export` 被 `/{record_id}` 遮蔽；JWT 密钥不再硬编码
